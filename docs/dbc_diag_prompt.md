# 给"公司电脑上的 agent"的 DBC 诊断提示词（复制即用）

用途：让另一台机器上的 agent 只读分析两个 DBC 的编码/结构/语法差异，用于定位
"为什么 A 文件无法被某个 Rust DBC 解析器（can-dbc 10.0.0）解析，而 B 文件可以"。

**给 Neil 的说明**：把下面代码块整段复制给那个 agent，并替换两个文件路径即可。
它不会导出文件全文，只输出结构量、编码判据、关键字计数、少量可打码片段 —— 可以先把输出过一眼再发我。

---

```
【任务】只读分析两个 Vector DBC 文件的编码、结构与语法差异。
背景：有一个 Rust 写的解析器（用 can-dbc 10.0.0）能解析 B 文件，但解析 A 文件失败。
需要你给出两份文件的逐项对照，用于定位差异。**绝对不要修改原文件**。

文件：
- A（解析失败）：<在此填写 A 的完整路径>
- B（解析正常）：<在此填写 B 的完整路径>

【逐项回答，每项都要分别给出 A 和 B 的结论】

1. 基本量
   - 字节数、行数、行尾类型（全 CRLF / 全 LF / 混合）
   - 前 8 个字节的十六进制（用来判断有没有 UTF-8 BOM = EF BB BF）

2. 编码判定（**最关键，请务必做严**）
   - 按**严格 UTF-8** 解码是否成功？（PowerShell 示例：
     `[System.Text.UTF8Encoding]::new($false,$true).GetString([IO.File]::ReadAllBytes($p))`
     抛异常 = 不是合法 UTF-8）
   - 非 ASCII 字节的总数；
   - 若严格 UTF-8 失败：**第一个非法字节的字节偏移 + 所在行号 + 该行完整原文**
     （可以把信号名/报文名打码成 XXX，但**保留引号、分号、方括号、逗号、缩进等标点**）
   - 若按 GB18030（代码页 936）解码：是否成功、解出的中文是否可读（给 1–3 个样例，可打码）

3. 关键字/段出现次数（逐条给数字，没有就写 0）
   - 重点（这些是"已知会让该解析器失败"的候选）：
     `CM_ BA_` ／ `BA_DEF_REL_` ／ `BA_DEF_DEF_REL_` ／ `BA_REL_` ／ `BU_SG_REL_` ／
     `BU_EV_REL_` ／ `BU_BO_REL_` ／ `BA_DEF_SGTYPE_` ／ `BA_SGTYPE_` ／ `SIGTYPE_VALTYPE_` ／
     `CAT_DEF_` ／ `CAT_` ／ `FILTER` ／ `EV_DATA_` ／ `ENVVAR_DATA_` ／ `SGTYPE_` ／
     `SGTYPE_VAL_` ／ `SIG_TYPE_REF_`
   - 确认存在性（这些是"已知能正常解析"的，只需有/无 + 条数）：
     `VAL_` ／ `VAL_TABLE_` ／ `SG_MUL_VAL_` ／ `SIG_VALTYPE_` ／ `SIG_GROUP_` ／ `BO_TX_BU_` ／ `EV_`

4. `NS_ :` 段
   - 把两个文件 `NS_ :` 段里列出的**每一个关键字逐行原样抄出来**（不要省略、不要归纳）
   - 明确指出两个文件的 NS_ 列表差异（只在 A 有 / 只在 B 有）

5. 头部段完整性
   - `VERSION` / `NS_ :` / `BS_:` / `BU_:` 四个段各是否存在；`BU_:` 后的节点名列表（可打码）

6. 结构量
   - `BO_` 报文条数、`SG_` 信号条数
   - 首 3 条 `BO_` 行、首 3 条 `SG_` 行的**原样文本**（名称可打码，标点必须保留）

7. 语法可疑点（逐条 yes/no；若 yes 给行号 + 该行原文，名称可打码）
   - 是否存在 `SG_` 行**结尾没有接收者**（形如 `... "" ;` 直接跟分号）
   - 是否存在 `SG_` 行缺 `[min|max]`、或单位引号不配对
   - 是否存在注释/字符串里出现未转义的 `"`（即某行的引号总数为奇数）
   - 是否存在缺失/多余的分号，或**一条语句跨多行**（未在同行的 `;` 结束）
   - 是否存在 `BO_` 的 ID 超过 0x7FF 但没带扩展位（0x80000000），或 ID 用十六进制/带符号写法
   - 是否存在 `SG_` 里 `@0`/`@1` 之外的位序标记，或 `m`/`M` 之外的多路复用标记

8. 中文出现的位置分类（每类给 1 个样例，可打码）：
   注释 `CM_` ／ 值表 `VAL_` ／ 信号名 ／ 报文名 ／ 节点名 ／ 属性字符串（`BA_DEF_`/`BA_` 里）

9. **差异清单（最重要的一条）**
   逐条列出"**只在 A 出现**"与"**只在 B 出现**"的：关键字/段、编码特征（BOM/非 UTF-8 字节）、头部段、
   结构写法差异。每条都要给证据（行号 + 原文片段或计数）。

【可选，若你有写文件的权限】把 A 复制一份到临时目录，**仅做编码转换**（内容不动，转成
UTF-8 无 BOM），给出临时文件路径 —— 用于后续"是否编码问题"的对照实验。**不要覆盖原文件。**

【输出要求】
- 按上面 1–9 编号组织，每个编号下写清"文件A："和"文件B："
- 不确定的写"无法确定"，**禁止猜测、禁止编造**；不要导出文件全文
- 最后给一段 3–5 行的"结论/最可能的差异"
```

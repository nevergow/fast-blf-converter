# v0.4.1 —— 宽表重采样崩溃修复 + 预览交互重做

这一版修的是**真问题**：CSV「多信号一张表 + 重采样」在进度 70% 左右**静默闪退**。
顺带把预览窗口的缩放/读数交互补齐、把界面上的废话删掉、把日志落到文件（以后再有异常能查）。

## 一、为什么会在 70% 闪退（根因）

70% 正好是「解码结束 → 合并导出开始」的分界点。合并宽表时，程序按
`G = (最晚时间 − 最早时间) × 重采样频率` **一次性分配整张时间网格**，而 `G` 没有任何上限：
- 每个信号还要再留一整列「可空浮点」（16 字节/格），峰值 ≈ `13~30 × G × 信号数`；
- 内存预算参数在**这个阶段根本没用上**；
- 分配失败 → Rust `handle_alloc_error` → 进程 `abort()`，`catch_unwind` 抓不到 →
  用户看到的就是**闪退、没有任何报错**。

关键结论：**触发点是「时间跨度 × 选中信号数」，不是文件大小。**
实测：144 MB / 2612 万帧 / 3.5 小时的文件只吃 1.6 GB；而一个 231 MB 的日志如果事件稀疏、
跨十几个小时，50 Hz 下 `G` 就会上百万，峰值轻松突破 10 GB。

## 二、修复

**1）安全网（先保证不再无声死掉）**
- `G` 用 checked 运算 + **硬上限 2000 万点**（50 Hz ≈ 111 小时），超限直接返回可读错误；
- **分配前预算闸门**：超过内存预算就返回结构化 `BAD_CONFIG`，消息里给出
  `t0 / t1 / 时长 / hz / G / S / 估算 MB / 预算 MB` 和「建议降到多少 Hz」，**绝不 abort**；
- 每个信号的存储从 `Vec<Option<f64>>`（16 B/格）改为 `Vec<f64>` + 1 bit 空值掩码；
- phase 1 每个文件单独 `catch_unwind`，内核 panic 变成 `errors[]` 而不是穿透成 `PanicException`。

**2）真修复：宽表重采样改成两遍式流式**
按 `CHUNK_ROWS = 20000` 行块处理：先按表/信号把行块重采样结果落到临时文件，
再逐块拼成 DataFrame 增量写出 CSV / Parquet。任何时刻都不持有 `G` 长度的中间数组。

| 实测（同一台机器，release） | 改前 | v0.4.1 |
|---|---|---|
| 600 s / 189 信号 / 50 Hz | 227 MB | **167 MB** |
| 12800 s / 2612 万帧 / 50 Hz（G=64 万） | 1588 MB | **863 MB** |
| 同文件 / **200 Hz（G 放大 4 倍）** | 预计 ~6.4 GB（必崩） | **793 MB** |
| 坏时间戳文件（跨度 23 天） | 卡死 >5 分钟 / 被 OOM 杀掉 | **0.14 s** 返回可操作错误 |

`G` 放大 4 倍峰值反而更低 —— 内存已经与网格行数解耦。

**3）输出逐字节不变**
600 s 与 12800 s 两个规模的 CSV，`sha256` 与改前**完全一致**（含 `hold` 与 `linear` 两种填充）。
这次只改「怎么算、怎么落盘」，没改「算出什么」。

## 三、日志（以后再有异常能查）

- 启动即写滚动日志：Windows `%LOCALAPPDATA%\fast_blf_converter\logs\gui.log`、
  macOS `~/Library/Logs/fast_blf_converter/gui.log`（10 MB × 5 份）；
- `faulthandler` 抓 native 崩溃栈、`sys/threading.excepthook` 抓未捕获异常、
  Rust `panic` hook 落同文件；
- 转换开始/结束各一行摘要；内核在合成宽表**前**写一行预检（`G / S / est_mb / budget_mb`）；
- 工具栏新增「📂 打开日志目录」；
- `Worker` 现在能捕获 `pyo3` 的 `PanicException`（原来它属于 `BaseException`，被漏掉了）。

## 四、预览窗口

- **轴内单轴缩放**：鼠标在 X 轴刻度上滚轮 = 只缩时间；在 Y 轴刻度上滚轮 = 只缩该轴的数值范围
  （Y 缩放纯显示层，**不重新取数**，实测 `view()` 调用次数不变）。
- **选框放大**：右键拖动（或 `Shift`+左键拖动）拉出选框，松手放大到所选区间；左键拖动仍然是平移。
- **FIT X / FIT Y / FIT ALL** 三个按钮（FIT Y 只贴合当前窗口的数值范围，不清时间轴）；双击画布 = FIT ALL。
- **光标读数条**：画布下方固定一条 `t = … / 各信号数值`，跟着光标实时更新。
- 修掉双击复位会「先变抓手、再多取一次数」的副作用。
- Y 轴刻度改为 nice-number 并按量程自适应精度（缩到很窄不会再出现三个一样的标签）。
